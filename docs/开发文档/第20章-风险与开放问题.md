### 20.1 风险分级口径
本章风险编号 `R-T*`（技术）、`R-P*`（产品）、`R-C*`（成本与延迟）、`R-L*`（合规与安全）。概率、影响各按 1–3 分，乘积 ≥6 为高、3–5 为中、≤2 为低；每条必须写可观测的触发信号（Trigger Signal）与缓解动作（Mitigation），否则降级为开放问题。风险在单次进度文档第 6 节滚动登记（第 22 章）。

### 20.3 开放问题（逐项给 2～3 方案与取舍）

- **Q1 编排层**：已按第 8 章结论定案为 C 方案（主流程 LangGraph + 多角色调度自建 loop），不再是开放问题；M1 末仅复核节点边界与版本锁定（第 8 章 §8.4）。
- **Q2 多角色同回合**：A. 串行（时序清晰，成本与延迟线性上升）；B. 一次调用批量生成多个 NPC 回复（省 token，但按角色切分难、单点失败影响大）；C. 玩家路径串行 + NPC 批量。**倾向 C**，M3 用 3 个 NPC 基准测试决定。
- **Q3 事件存储**：A. 单表 append-only（最简，规模上限低）；B. 事件表 + 每 N 回合快照（回放快，实现量中等）；C. 外部事件库（违反“禁止额外运行时”约束）。**倾向 B**，M2 先落地单表 + 快照。
- **Q4 自由制造**：A. 强模型直出完整结果（链路短，数值不可控）；B. 智能体出草案、数值由 `calculate_craft_result` 重算（多一道校验可兜底）；C. 全确定性路径（无自由度）。**倾向 B**，M4 落地，违反 Schema 或状态一致性一律拒绝写入。
- **Q5 供应商回退**：A. 单供应商 + LLMClient 回退层（同厂故障无解）；B. 双供应商并行灰度（成本与验证翻倍）；C. 只走 OpenAI 兼容协议换 base_url（受协议差异限制）。**倾向 A+C**，M5 完成故障演练；LiteLLM 只用根目录 MIT 部分并锁版本。
- **Q6 认证方案（v0.2 前端）**：A. 本地单机无账号（默认，服务只绑 `127.0.0.1`、不鉴权；风险是同机其他进程可访问）；B. 部署加鉴权（API Key 或会话 Cookie + CSRF 防护；成本是多一层配置与测试）；C. 中间态：默认 localhost 免鉴权，监听非回环地址时强制启用鉴权。**倾向 A（本地默认）+ C（部署前切换）**，M6 交付以 A 验收，部署形态在 M6 前写进第 23 章与 `docs/PROGRESS.md`。
- **Q7 流式叙事（v0.2 前端）**：A. 首版不做，整屏返回（80–150 字/屏符合 2G 风格，实现最简）；B. SSE 流式推送（体验好，但需连接治理、断线重连与“提交前生成/提交后返回”边界）；C. 轮询状态接口（简单但延迟与请求量增加）。**倾向 A**：首版只保留 `/api/v1/turns` 同步接口；M6 后按体验数据评估 B。若做 B，叙事流不得改变第 4、9 章的提交顺序。

### 20.4 复审与升级机制
每个里程碑结束由 lead 主持复审：关闭消失项、上调频繁触发项、把新风险补进本章并同步到下一次进度文档第 6 节。任一高风险触发即升级为 lead 决策，结论回写本章“关联”列与 `docs/PROGRESS.md` 风险摘要，不接受口头处理；未定项以 Q 编号挂账，在对应里程碑前一个进度文档内关闭或转为 ADR。

复用判断与拼接边界：
1. Evennia 已按第 11 章结论判为 `放弃`（3.10 不兼容、绑定 Django/Twisted、会形成第二套状态权威）；Text-Game-Engine 与 tldw_server 只借模式不借代码，CAS 与 lease 语义写进 GameEngine（第 11 章）；单维护者项目不上核心路径。
2. LiteLLM 与 LangGraph 可依赖但必须包住：业务代码只调用 LLMClient（第 12 章），LangGraph 只在 `orchestration/` 出现，失败分别由 LLMClient 降级链与 TurnOrchestrator 超时分支兜住；Pydantic 是 Schema 唯一来源，升级只接受 minor。

### 本章结论
1. 最高优先级是 R-T1“两套状态权威”：Evennia `放弃`（3.10 不兼容），Text-Game-Engine 与 tldw_server（GPL-3.0-only）一律 `参考设计`，不 pip 依赖、不拷贝源码，CAS 与 lease 由自研 GameEngine 实现。
2. LiteLLM 是许可证分层的候选：只用根目录 MIT 代码并锁定 1.108.x 版本，禁止拷贝 `enterprise/` 与前端；LangGraph 锁定 1.2.x minor 并隔离在 `orchestration/`；两者均按第 19 章版本锁定与扫描清单执行。
3. 成本与延迟风险（R-C1、R-T4）必须在 M2 就埋点，验收以“每回合成本环比”和“1000 回合回放 ≤ 30 s”卡住，晚做无法回填数据。
4. Q1 已按第 8 章定案（引用）；Q2–Q7 按编号挂账，其中 Q6（认证）、Q7（流式叙事）为 v0.2 前端新增，各自在对应里程碑前一个进度文档内关闭；未关闭按“倾向”方案执行，不允许留空。
5. 所有风险以 R-* 编号滚动登记，进度文档第 6 节与 `docs/PROGRESS.md` 风险摘要保持同一编号体系（第 22 章），每里程碑末复审一次。
6. v0.2 前端风险（R-L3 上传/XSS、R-C2 生成内容安全与成本、R-T6 npm 供应链、R-P2 浏览器兼容）随第 23 章 M6 验收；Node 仅构建期、运行时不依赖 Node，上传与生成内容一律先过 Schema 与内容安全。
