### 20.1 风险分级口径
本章风险编号 `R-T*`（技术）、`R-P*`（产品）、`R-C*`（成本与延迟）、`R-L*`（合规与安全）。概率、影响各按 1–3 分，乘积 ≥6 为高、3–5 为中、≤2 为低；每条必须写可观测的触发信号（Trigger Signal）与缓解动作（Mitigation），否则降级为开放问题。风险在单次进度文档第 4 节「下一步与风险」滚动登记（第 22 章轻量模板）。

### 20.3 开放问题（逐项给 2～3 方案与取舍）

- **Q1 编排层**：**已定案（2026-11-09，M4 前，追认）主流程采用自建显式 loop**（多角色提案动态循环 + CAS 单事务 + 冲突重试只重裁决，图只包流程外壳收益低；见第 8 章 §8.4 回写）；LangGraph 仅保留第 16 章 `graph.py` 可选封装，留 M6 后或出现 HITL / 跨进程 durable execution 需求时评估。不再是开放问题。
- **Q2 多角色同回合**：A. 串行（时序清晰，成本与延迟线性上升）；B. 一次调用批量生成多个 NPC 回复（省 token，但按角色切分难、单点失败影响大）；C. 玩家路径串行 + NPC 批量。**已定案（2026-11-09，M4 前，D-M4-12）采用 C**：玩家路径串行 + NPC 确定性计划/批量（M3 以两名拾荒者 + 确定性计划表验证）；真实 LLM 角色 Agent 的批量策略随 M5 接线复审。
- **Q3 事件存储**：A. 单表 append-only（最简，规模上限低）；B. 事件表 + 每 N 回合快照（回放快，实现量中等）；C. 外部事件库（违反“禁止额外运行时”约束）。**已定案（2026-11-09，M4 前，D-M4-12）采用 B**：事件单表 append-only + 每 N 回合快照（M2 已落地 events/snapshots 与 CAS；M4 沿用，不引入外部事件库）。
- **Q4 自由制造**：A. 强模型直出完整结果（链路短，数值不可控）；B. 智能体出草案、数值由 `calculate_craft_result` 重算（多一道校验可兜底）；C. 全确定性路径（无自由度）。**已定案（2026-11-09，M4 前，D-M4-12）采用 B**：M4 落地，违反 Schema 或状态一致性一律拒绝写入；M4 不接 Resolver（D-M4-3，自由制造直接交 GameEngine）。
- **Q5 供应商回退**：A. 单供应商 + LLMClient 回退层（同厂故障无解）；B. 双供应商并行灰度（成本与验证翻倍）；C. 只走 OpenAI 兼容协议换 base_url（受协议差异限制）。**倾向 A+C**，M5 完成故障演练；LiteLLM 只用根目录 MIT 部分并锁版本。
- **Q6 认证方案（v0.2 前端）**：A. 本地单机无账号（只绑 `127.0.0.1`，默认）；B. 部署加鉴权（API Key/会话 + CSRF 防护）；C. 中间态（监听非回环地址时强制鉴权）。**定案（2026-11-10，D-M6-6）：A+C**——首版按 A 验收（127.0.0.1 单机无鉴权），监听非回环地址必须强制鉴权（C）作为部署门；公告口径不得早于该门。
- **Q7 流式叙事（v0.2 前端）**：A. 首版整屏返回（默认，最简）；B. SSE 流式（需连接治理与提交边界）；C. 轮询状态。**定案（2026-11-10，D-M6-6）：A**——首版整屏返回；B 在 M6-v1 后按体验复评，若做 B 不得改变第 4、9 章的提交顺序。
- **Q8 自动代码审查（v0.3）**：A. 仅人工 review（默认，最省成本但吞吐受限）；B. CI 必跑 lint/type/架构测试/secret scan，AI review 仅作辅助（推荐）；C. 独立审查 Agent 双盲复核。**已定案（2026-11-09，M4 前，D-M4-12）采用 B**：CI 必跑 lint/type/架构测试/secret scan，AI review 仅辅助；不引入独立审查 Agent（C 暂不评估）。
- **Q9 CI 沙箱（v0.3）**：**已定案（2026-11-09，M4 前）方案 B-lite**：GitHub 托管 runner 作为临时容器边界 + 每个 job `timeout-minutes` 兜底 + quality job 不注入任何密钥 + 测试套件默认禁网（`tests/conftest.py` autouse socket guard，只放行本机回环；真实 LLM 一律 FakeLLM/cassette）。完整容器沙箱（固定镜像 + `--network none`）留 M6 后按需评估。
- **Q10 上下文白名单（v0.3）**：**已定案（2026-11-09，M4 前）方案 B**：仓库根 `.aiignore` 声明禁止进入 AI 上下文的路径（`.env*`、`.work/`、`artifacts/`、`data/`、`*.db`、`.venv/` 等）+ `scripts/check_secrets.py` pre-commit 门禁 + 文档白名单说明（R-L5 缓解链）；未引入 RAG 自动检索。


### 20.4 复审与升级机制
每个里程碑结束由 lead 主持复审：关闭消失项、上调频繁触发项、把新风险补进本章并同步到下一次进度文档第 4 节。任一高风险触发即升级为 lead 决策，结论回写本章“关联”列与 `docs/PROGRESS.md` 风险摘要，不接受口头处理；未定项以 Q 编号挂账，在对应里程碑前一个进度文档内关闭或转为 ADR。

**2026-11-09 复审记录（M3 结束 / M4 前）**：Q1 追认自建 loop；Q9 取 B-lite、Q10 取 B；Q2/Q3/Q4/Q8 定案（见 §20.3，D-M4-12）；R5/R6 补入风险表并建立 R-* 归口（见 §20.2.2）；R-L3 状态词统一为「打开」（M6 范围，尚未进入）。

### 本章结论
1. 最高优先级是 R-T1“两套状态权威”：Evennia `放弃`（3.10 不兼容），Text-Game-Engine 与 tldw_server（GPL-3.0-only）一律 `参考设计`，不 pip 依赖、不拷贝源码，CAS 与 lease 由自研 GameEngine 实现。
2. LiteLLM 是许可证分层的候选：只用根目录 MIT 代码并锁定 1.108.x 版本，禁止拷贝 `enterprise/` 与前端；LangGraph 锁定 1.2.x minor 并隔离在 `orchestration/`；两者均按第 19 章版本锁定与扫描清单执行。
