### 13.1 结论先行
制造是**两个系统**：常规配方走纯函数 `calculate_craft_result`，全程不调用 LLM；只有「无匹配配方 + 玩家明确描述组合 + 自由制造开关打开」三条件同时成立，才触发制造 Agent 生成草案（`CraftOutput`→`CraftDraft`，校验通过后由框架重算数值并组装草稿事件）。自由制造开关为 `TEXTGAME_FREE_CRAFT_ENABLED`（默认 false，第 16 章 §16.5）；M4 生产默认关闭、**不接真实 LLM**（M5 出口附加项），仅测试以 FakeLLM 覆盖；预算判定归 M5 成本治理（第 12 章），M4 不做预算检查。生成路径只允许 LLM 给性质、命名、描述与效果 ID，**所有数值由框架重算**，LLM 给的任何数字一律丢弃（草案 Schema 出现数值字段即 `SCHEMA_VIOLATION`）。

### 13.2 配方数据模型与制造域契约类型
制造域契约类型统一由本章定义（第 5 章 5.6 表引用本章，避免全队出现未定义类型）；命名链为第 8 章 `CraftOutput`（Agent 原始输出，字段名以本章 `CraftDraft` 为准）→ 本章 `CraftDraft`（规范化草案）→ 本章 `CraftProposal`（M5 契约：校验通过后交 Resolver 的领域提案；M4 不组装，D-M4-3）。`CraftRequest` 为服务层入参（第 6 章）。材料与产物按「模板/实例分离」建模：配方/草案/事件中的材料引用一律用物品模板键 `ItemTemplateId`（复用第 5 章 §5.7 定义，规范写法 `item.<name>`，如 `item.iron_ingot`；`item_<name>` 亦接受，但 `item_<26位ULID>` 是实例 ID、不得作模板键），背包与产出仍是物品实例 `ItemId = item_<26位ULID>`（第 5 章 ID 规则）；物品实例的 `Item.tags` 含其模板键（M4 匹配口径，第 5 章按此补说明），服务层据此把 `Character.inventory: list[ItemId]` 聚合为 `dict[ItemTemplateId, int]`（数量 = 同模板实例重复项数，背包上限 64 不变）。最小契约定义如下：

```python
class CraftMode(str, Enum):
    RECIPE = "recipe"   # 有配方：确定性 calculate_craft_result
    FREE = "free"       # 无配方：CraftAgent 生成草案

class ItemTemplate(BaseModel):
    """物品模板：配方内嵌的产出/副产物定义（回放不依赖配方目录，D-M4-1）。"""
    template_id: ItemTemplateId
    name: str = Field(min_length=1, max_length=32)
    description: str = Field(max_length=500)
    tags: list[str] = Field(default_factory=list, max_length=7)   # 实例化时前置模板键，实例 tags ≤8
    stats: dict[str, int | float] = Field(default_factory=dict)
    rarity: Literal["common", "uncommon", "rare", "epic", "legendary"] = "common"
    stackable: bool = False

class CraftRequest(BaseModel):
    mode: CraftMode
    recipe_id: str | None = None          # RECIPE 必填
    free_description: str | None = None   # FREE 必填（玩家原话，≤200 字）

class CraftInput(BaseModel):
    template_id: ItemTemplateId
    qty: int = Field(ge=1)
    role: Literal["material", "tool", "catalyst"]

class QualityBand(BaseModel):
    min_roll: float = Field(ge=0.0, le=1.0)
    quality: Literal["poor", "common", "fine", "masterwork"]

class Byproduct(BaseModel):
    template_id: ItemTemplateId
    qty: int = Field(ge=1)
    chance: float = Field(ge=0.0, le=1.0)

class CraftStateSlice(BaseModel):
    """calculate_craft_result 的确定性输入：只含本次制造所需视图。"""
    actor_id: CharacterId
    inventory: dict[ItemTemplateId, int]   # 服务层按实例模板标签聚合
    skill_levels: dict[str, int]           # M4 恒为 {}（D-M4-2）
    station_id: str | None = None          # 房间 ambient_tags 的 station.<name>（D-M4-9）
    next_seq: int = Field(ge=1)            # = 存档 last_seq + 1，服务层注入（D-M4-4）

class CraftResult(BaseModel):
    ok: bool
    success: bool
    consumed: list[CraftInput]             # 实际扣除项，tool 不消耗（D-M4-8）
    produced: list[CraftInput]             # role 固定 "material"（无语义，D-M4-8）
    byproducts: list[Byproduct] = Field(default_factory=list)  # 仅实际触发项
    quality: str | None = None
    rng_seed: int = Field(ge=0, le=0x7FFF_FFFF_FFFF_FFFF)
    reason: str | None = None

class CraftDraft(BaseModel):
    """CraftOutput 规范化后的草案：只含名称/材料/工位/步骤，禁止数值字段。"""
    item_name: str = Field(min_length=1, max_length=30)
    output_template_id: ItemTemplateId | None = None
    inputs: list[CraftInput]
    station: str | None = None
    steps: list[str] = Field(default_factory=list, max_length=8)

class CraftItemView(BaseModel):
    """CraftAgent 私有输入中的背包行（服务层投影，不暴露 GameState）。"""
    item_id: ItemId
    template_id: ItemTemplateId
    name: str
    qty: int = Field(ge=1)

class CraftView(BaseModel):
    """CraftAgent 私有输入（M4 由服务层投影；不改 PerceptionSlice，A-28）。"""
    actor_id: CharacterId
    inventory: list[CraftItemView]
    station_id: str | None = None
    known_recipe_ids: list[str] = Field(default_factory=list)
    free_description: str = Field(min_length=1, max_length=200)

class CraftProposal(BaseModel):
    """M5 契约（M4 不组装、不交 Resolver，D-M4-3）：校验通过后的领域提案。"""
    proposal_id: str
    actor_id: CharacterId
    turn_id: int
    reason: str
    proposed_recipe: dict
    narrative_hint: str | None = None
```

**实例化前后的载荷分工（N-01 / D-M4-1）**：`CraftResult` 是**实例化前**的模板级结果——`consumed`/`produced`/`byproducts` 只含 `ItemTemplateId` 与数量；实例化由 `instantiate_craft_result` 完成，产出与副产物的实例 ID（`item_<26位ULID>`）与完整 `Item` 定义**只出现在事件 `result.produced_items`** 中（回放据此写 `state.items` 与背包）。reducer 扣材料按 `result.craft.consumed` 的模板键与数量、产出入包按 `result.produced_items` 顺序（第 14 章 §14.7）。

配方与确定性输入模型：
```python
class Recipe(BaseModel):
    recipe_id: str
    name: str
    version: int = 1
    inputs: list[CraftInput]
    output_template_id: ItemTemplateId
    output_qty: int = 1
    station: str | None = None              # 工位名，与房间 ambient_tags 的 station.<name> 同串（D-M4-9）
    skill_req: dict[str, int] = Field(default_factory=dict)   # M4 不校验（D-M4-2）
    base_success_rate: float = Field(ge=0.0, le=1.0)
    quality_bands: list[QualityBand]
    byproducts: list[Byproduct] = Field(default_factory=list)
    item_templates: dict[ItemTemplateId, ItemTemplate]   # 产出/副产物 Item 定义（D-M4-1）
```
`Recipe` 交叉校验：`output_template_id` 与每个 `byproduct.template_id` 必须出现在 `item_templates` 中，`item_templates` 的键等于元素 `template_id`；`quality_bands` 按 `min_roll` 升序、必须从 0.0 起覆盖全部掷骰区间，命中档取满足 `min_roll ≤ roll` 的最高一档（A-26③）。配方以 JSON 存放（JSON-only：标准库 `json`，无新增依赖；D-M4-6）于 `src/textgame/data/recipes/*.json`，随包用 `importlib.resources` 读取；启动时校验（重复 `recipe_id`/非法 JSON/未知字段即启动失败）并注册进 `RecipeCatalog`/`CraftService`；`recipe_id` 全局唯一，`version` 变更不允许原地修改，必须新增版本（事件回放要能还原旧配方语义，见第 14 章）。数据目录需在 `.gitignore` 加负向规则 `!src/textgame/data/`（第 16 章）。确定性入口签名固定为：

```python
def calculate_craft_result(
    state: CraftStateSlice,
    recipe: Recipe,
    actor_id: CharacterId,
    rng_seed: int,
) -> CraftResult: ...
```
该函数纯函数、无 IO、同一 `rng_seed` 必得同一结果；`rng_seed` 由服务层按 `derive_seed(save_seed, turn_id, actor_id, "craft_item", next_seq)` 派生后传入（`next_seq` 见 `CraftStateSlice`；第 10 章）——`ctx.save_seed` 必须由编排层/`Resolver` 绑定**该存档快照的 `rng_state.save_seed`**（D-M4-14：禁止用组合根默认种子，否则非默认 seed 存档的 craft 种子/实例 ID 会与 `EventLog.stamp` 不一致）；**签名不变、不扩 `ToolContext` 六字段**（D-M4-4），因此事务回滚时不需要回滚 RNG 状态。约束：玩家 `craft_item` 事件必须是本次提交批次的首条事件（编排层 player→npc 顺序保证，M4 以断言测试覆盖），否则 `EventLog.stamp` 派生的 `rng_seed` 将与 `result.craft.rng_seed` 不一致。`CraftService` 只是服务入口包装：先解析 `ctx`/`recipe_id` 与背包上下文，再调用该领域函数（服务层接口见第 6 章）。

示例配方 JSON：
```json
{"recipe_id":"recipe.iron_sword","name":"铁剑","version":1,
 "inputs":[{"template_id":"item.iron_ingot","qty":2,"role":"material"},
           {"template_id":"item.oak_handle","qty":1,"role":"material"},
           {"template_id":"item.forge_hammer","qty":1,"role":"tool"}],
 "output_template_id":"item.iron_sword","output_qty":1,"station":"station.forge",
 "skill_req":{},"base_success_rate":0.85,
 "quality_bands":[{"min_roll":0.0,"quality":"common"},{"min_roll":0.8,"quality":"fine"}],
 "byproducts":[{"template_id":"item.iron_slag","qty":1,"chance":0.25}],
 "item_templates":{
   "item.iron_sword":{"template_id":"item.iron_sword","name":"铁剑","description":"可靠的铁制长剑","tags":["weapon","sword"],"stats":{"attack":3},"rarity":"common","stackable":false},
   "item.iron_slag":{"template_id":"item.iron_slag","name":"铁渣","description":"锻造剩下的碎铁","tags":["material"],"stats":{},"rarity":"common","stackable":true}}}
```

示例中的 `item.*` 为物品模板键（`ItemTemplateId`，复用第 5 章 §5.7；`item_<26位ULID>` 为实例 ID），`recipe.*` 为配方键；配方 JSON 不写实例 ID，真实实例 `item_<26位ULID>` 按第 5 章 ID 规则由框架确定性派生（见下）。

实例化规则（D-M4-1）：产出/副产物实例 ID 由框架确定性派生 `derive_item_id(save_seed, turn_id, actor_id, craft_kind, event_seq, ordinal)`（blake2b → Crockford Base32 26 位，形如 `item_<26>`；`craft_kind` 区分 `CRAFT_DETERMINISTIC`/`CRAFT_GENERATED`），禁止 `uuid4`/`random`，参数相同必得同一 ID。实例化时 `Item.tags` 以模板键（`item.<name>`）为首、再接模板 tags（≤7，保证实例 tags ≤8）。事件 `result.produced_items` 记录完整 `Item` 定义，回放只读事件、不依赖配方目录；投影时按 `result.craft.consumed` 的模板键与数量，从 `Character.inventory` 按顺序移除同模板实例（见第 14 章 reducer）。

### 13.3 路径切换策略
| 条件 | 走哪条路径 | 记录 |
| --- | --- | --- |
| 有配方，材料/工具/工位满足（技能校验后移，D-M4-2） | 确定性 `calculate_craft_result` | Event `CRAFT_DETERMINISTIC`（含 rng_seed；掷骰失败同事件 `success=false`） |
| 前置校验失败（材料不足/缺工具/工位不匹配/参数非法/自由草案未过 Schema） | 确定性拒绝，不掷骰 | `Result(ok=false)`、零事件；失败提案由编排层照常写 `audit_events`（行状态 `committed`/`aborted`、逐提案 `verdict` 记 `rejected`；与 m2/m3 同口径） |
| 无配方，自由制造开关开（`TEXTGAME_FREE_CRAFT_ENABLED=true`，非生产默认） | 生成路径：`CraftAgent`→`CraftDraft`→`CraftService` 校验与重算 | Event `CRAFT_GENERATED` + `proposal_hash`/`prompt_version` |
| 无配方，开关关闭（M4 生产默认）或未接 LLM | 返回 `NOT_ALLOWED`（策略拒绝；「确实无配方」才回 `NOT_FOUND`） | 零事件；失败提案照常写 `audit_events`（与 m2/m3 同口径） |
| 智能体想覆盖确定性结果 | 禁止；M4 无可覆盖通道（`craft_item` 保持 `resolution_policy=deterministic`） | `CraftProposal` 仅为 M5 契约保留（D-M4-3） |

**M4 事件语义（D-M4-5）**：① 前置校验失败（材料/工具/工位/参数/自由草案未过 Schema）= `Result(ok=false)`、**零事件**；失败提案由编排层照常写 `audit_events`（行状态 `committed`/`aborted`、逐提案 `verdict` 记 `rejected`；与 m2/m3 同口径）。② 掷骰失败（成功率未过）= 提交一条 `CRAFT_DETERMINISTIC`：`result.craft.success=false`、`consumed`/`produced`/`byproducts` 为空，状态仅推进 `turn`/`world_time`。③ 成功 = 配方路径 `CRAFT_DETERMINISTIC`、自由路径 `CRAFT_GENERATED`；`params`：配方路径含 `mode/recipe_id/recipe_version`，自由路径含 `free_description_sha256/proposal_hash/prompt_version`；`result.craft` 为 `CraftResult` JSON，`result.produced_items` 为完整 `Item` 定义列表；`rng_seed` 由 `EventLog.stamp` 派生且必须等于 `result.craft.rng_seed`。`CRAFT_REJECTED` M4 **不产生**，仅预留 identity reducer（`applied=false` 语义留 M5，第 14 章）。

**M4 编排链路与 Resolver 边界（D-M4-3 / D-M4-13）**：M4 制造（recipe 与 free 两条）作为普通 `DESTRUCTIVE` 工具复用既有 M3 编排链路——玩家 `craft_item` 仍是 Proposal：`ProposalQueue` → 确定性 `Resolver`（m4 无 NPC Agent，故无跨角色冲突、无 Judge 覆盖，`resolution_policy=deterministic`）→ `ToolGate` → `CraftService` → `GameEngine` 单事务提交，失败提案由编排层照常写 `audit_events`。D-M4-3 的「不接 Resolver」仅指：自由制造草案本身不经裁决、`CraftProposal` 不进入 `ProposalQueue`（仅作 M5 契约保留）；M5 接线真实 LLM 前必须把生成调用迁移到 pre-queue，否则违反第 11 章 Resolver 纯函数约束。

「近似配方」判定**待定**，首版不做：① 精确匹配（推荐，行为可预测）；② 材料替换表（如石头替代铁，需策划维护替换矩阵）；③ 相似度匹配交给 Agent 提议、Resolver 审批（成本高、可解释性差）。

### 13.4 自由制造生成路径
1. 制造 Agent 只接收服务层投影的私有视图 `CraftView`（背包清单、当前工位、已知配方 ID 列表、玩家原话），不接收全局 `GameState`，也不接收其他角色数据（第 9、11 章）；M4 不扩 `PerceptionSlice`，由服务层从私有感知切片投影（A-28；第 5/8 章按此回写）。
2. 输出 `CraftOutput`（第 8 章，`CraftAgent` 的原始输出）→ 本层规范化为 `CraftDraft`：`item_name / output_template_id / inputs / station / steps`；字段名以本章为准（第 8 章 `slots/materials` 按 A-28 回写映射），Schema 中**不提供任何数值字段**（无 stats、无 damage）。
3. Schema 校验（pydantic strict + jsonschema Draft 2020-12）→ 失败进入一次修复重试；仍失败 → `Result(ok=false)`、`SCHEMA_VIOLATION`、零事件（M4 不产生 `CRAFT_REJECTED`）。
4. 状态一致性检查（全部在 `CraftService` 内，失败即拒绝；M4 最小集，D-M4-7）：输入模板必须在该角色背包且数量足够；工具/工位必须存在且可用（`tool` 不消耗，D-M4-8；工位 = 房间 `ambient_tags` 中的 `station.<name>`，D-M4-9）；`inputs` 只能引用背包内实例的模板；名称 1～30 字、`steps` ≤8；不得引用未知实体或他人所有物；产出模板必须在 `item_templates` 内；草案不得含任何 LLM 数值字段（`extra="forbid"` 直接拦截）。后移 M5/内容系统：稀有度上限、材料强度映射表、效果 ID 白名单、技能校验（D-M4-2）。
5. 数值重算：`CraftService` 把草案折算为临时 `Recipe`（产出实例 ID 由框架派生，`base_success_rate`/质量档用框架固定值，不接收 LLM 数值），再用同一 `calculate_craft_result` 重算；生成路径下 `stats_claim` 字段不存在，出现即 `SCHEMA_VIOLATION`；产出 `stats` 取 `item_templates` 的固定值。
6. 校验通过后 `CraftService` 组装 `CRAFT_GENERATED` 草稿事件并返回 `Result(ok=True, events=[草稿 Event], data={"craft": CraftResult})`；它不开启/提交事务、不调 `GameEngine`。玩家 `craft_item` Proposal 走既有 M3 编排链路：`ProposalQueue` → 确定性 `Resolver`（其内经 `ToolGate` 调 `CraftService` 取草稿事件）→ `GameEngine.submit(expected_version, events, idempotency_key)`（D-M4-13；`scenario="m4"` 无 NPC Agent，故无跨角色冲突、无 Judge 覆盖）。D-M4-3 的「不接 Resolver」仅指自由制造草案本身不经裁决、`CraftProposal` 不入 `ProposalQueue`（仅 M5 契约保留），M5 接线真实 LLM 前须迁 pre-queue，否则违反第 11 章 Resolver 纯函数约束。
7. 失败时服务层返回 `Result(ok=false)` 且不带可提交事件，材料与 GameState 的零变更由 `GameEngine` 事务回滚保证（见 13.5）；M4 生产默认 `TEXTGAME_FREE_CRAFT_ENABLED=false`、`CraftAgent` 不接真实 LLM（仅测试注入 FakeLLM），开关关闭时自由路径直接拒绝。
**R-19 收口（2026-11-12，D-R6-3）**：自由制造草案改为 **pre-queue 两段式**——编排层在提案入队/裁决前预生成一次 `CraftDraft`（`orchestration/pre_queue.py`；`ToolGate`/`CraftService.prepare_free_craft`，含一次 Schema 修复），`Resolver.resolve(..., prepared_crafts=...)` 按 `proposal_id` 透传载荷后由 `CraftService._execute_prepared_free_craft` 纯校验/`calculate_craft_result` 重算。**Resolver 内零 LLM 调用**（`ctx.caller=="resolver"` 无载荷→`INVALID_INPUT`，永不回落生成器）；CAS 重试复用同一载荷；旧服务内生成路径只保留给 M2/直接 Gate（caller=player）。默认关闭/离线装配与旧 golden 逐字不变。

示例 `CraftProposal`（M5 契约，M4 不组装，仅示意字段口径）：
```json

 "proposed_recipe":{"name":"简易电击棒","output_template_id":"item.makeshift_taser",
   "inputs":[{"template_id":"item.oak_handle","qty":1,"role":"material"},

```

```json
  {"path": "draft.stats", "rule": "NO_LLM_NUMBERS"}]},

```
示例中的 `item.*` 为物品模板键（复用第 5 章 §5.7 定义），`char.player_1`/`p-0007` 等为示意 ID；真实实例 `item_<26位ULID>` 按第 5 章 ID 规则由框架确定性派生（§13.2、D-M4-1）。

### 13.5 失败回滚与提交边界
提交边界固定：`CraftService.craft(...)` 只做校验、数值重算与**草稿事件**组装，返回 `Result(ok=True, events=[草稿 Event], data={"craft": CraftResult})`（自由制造路径的 `proposal_hash`/`prompt_version` 记入事件 `params`，不回填 `data`）；它不写库、不 `session.commit()`、不调 `EventLog.append()`、也不调 `GameEngine.submit()`——服务层与 GameEngine 的边界与第 6 章一致。

真正的事务提交由编排层调用唯一写入者完成：`GameEngine.submit(expected_version, events, idempotency_key)` 在一个事务里依次做 ① 校验 `game_state_current.version`（接口字段 `expected_version`；乐观并发控制，Optimistic Concurrency Control，CAS，见第 14 章）→ ② 扣材料、产出入包（**M4 不更新技能经验**，D-M4-2；材料按 `consumed` 的模板键与数量从背包逐件扣减，产出按 `result.produced_items` 写入 `items`）→ ③ `EventLog.stamp()` 盖章并追加事件 → ④ 计算 `state_hash` 并提交；任一步失败由 `GameEngine` 回滚整个事务并返回 `CONFLICT`/`INTERNAL`，`CraftService` 只把该 `Result` 透传给调用方，材料与产物零变更。

失败尝试的审计由编排层（不是服务层）负责（**编排队列统一记录**；m2/m3/m4 同一链路，失败提案照常写审计行）：状态变更事件随事务回滚，但失败尝试通过独立事务写 `audit_events`（best-effort），记录 `turn_id/actor/method/error_code/proposal_hash`。幂等由编排层 turn 幂等键（`turn:{game_id}:{Idempotency-Key}`）与 `events` 复合主键 `(game_id, seq)` 覆盖，**M4 不新增 `craft_id` 唯一索引、不加迁移**（D-M4-10）；崩溃恢复依赖已提交事件重放 + 幂等表（`turns` 表/inflight 租约 M4 不实现，列为 M5 计划，不作为 M4 依赖）。

### 13.6 M4 落地口径（2026-11-09 定案）
本节汇总 M4 实现必须遵守的 D-M4-* 口径；本章正文若与本节冲突，以本节为准。

| 决策 | M4 要求 | 后移/说明 |
| --- | --- | --- |
| D-M4-1 模板/实例分离 | 材料引用一律 `ItemTemplateId`（`item.<name>`，复用第 5 章 §5.7）；新增 `ItemTemplate`/`CraftInput.template_id`/`Recipe.output_template_id`/`item_templates`/`Byproduct.template_id`；产出实例 `item_<26位ULID>` 由 `derive_item_id(...)` 确定性派生，事件 `result.produced_items` 记完整 `Item` | 第 5 章 `Item`/`GameState` 字段不改 |
| D-M4-2 技能后移 | `skill_levels={}`、`skill_req` 不校验；`Character` 不加 `skills` 字段；不更新技能经验、不新增技能/经验事件 | 技能系统随 M5/内容系统 |
| D-M4-3 Resolver 边界 | 制造作为普通 `DESTRUCTIVE` 工具复用 M3 编排链路（Proposal→Queue→确定性 Resolver→ToolGate→CraftService→GameEngine）；m4 无 NPC Agent → 无跨角色冲突、无 Judge 覆盖；`CraftProposal` 仅 M5 契约（草案不入队） | M5 接线前迁 pre-queue |
| D-M4-4 种子 seq 来源 | `CraftStateSlice.next_seq`（=`last_seq+1`）由服务层注入，`derive_seed(..., "craft_item", next_seq)`；玩家 craft 事件须为提交批次首条；不扩 `ToolContext` 六字段 | M4 加断言测试 |
| D-M4-5 事件语义 | 前置失败=`Result(ok=false)` 零事件+审计（失败提案照常写 `audit_events`，m2/m3/m4 同口径）；掷骰失败=`CRAFT_DETERMINISTIC(success=false)`；成功=`CRAFT_DETERMINISTIC`/`CRAFT_GENERATED`；`rng_seed` 必须等于 `result.craft.rng_seed` | `CRAFT_REJECTED` 仅 identity reducer |
| D-M4-6 配方数据与开关 | JSON-only（标准库 `json`）、`src/textgame/data/recipes/*.json`、`importlib.resources` 读取、启动校验失败即退出；`TEXTGAME_FREE_CRAFT_ENABLED` 默认 false | 预算归 M5 成本治理 |
| D-M4-7 017 校验最小集 | 背包数量/工具/工位/名称 1–30 字/`steps` ≤8/未知实体/产出模板在 `item_templates`/无数值字段（`extra="forbid"`） | 稀有度上限、材料强度映射、效果白名单、技能后移 |
| D-M4-8 配料语义 | `role ∈ {material,tool,catalyst}`；tool 不消耗；`produced` 复用 `CraftInput` 且 `role` 固定 `material`（无语义）；`byproducts` 仅实际触发项；`consumed` 记实际扣除（含 qty）；`CraftResult` 为实例化前模板级结果，实例 ID 与定义只在事件 `produced_items`（N-01） | M5 可改 `ItemStack` |
| D-M4-9 工位建模 | 工位 = 房间 `ambient_tags` 中的 `station.<name>`（如 `station.forge`）；不新增 `Station` 实体、不改 `GameState`；`Recipe.station` 为同名字符串 | — |

**D-M4-13（2026-11-09 补定）**：M4 制造（recipe 与 free 两条）作为普通 `DESTRUCTIVE` 工具复用既有 M3 编排链路（Proposal → `ProposalQueue` → 确定性 `Resolver` → `ToolGate` → `CraftService` → `GameEngine` 单事务）；m4 场景无 NPC Agent → 无跨角色冲突、无 Judge 覆盖；失败提案照常写 `audit_events`（与 m2/m3 同口径）。D-M4-3 的「不接 Resolver」仅约束自由制造草案不入队，M5 接线前迁 pre-queue 的约束不变。

复用判断与拼接边界：evennia 的制造 contrib 无法直接拷贝——它继承 evennia 的 command/object/spawner，搬进来等于引入第二套状态与命令层；只借鉴「配方 = 若干材料 + 工具 → 产物」的匹配结构与 `pre/do/post` 钩子顺序，错误类型 `CraftingValidationError` 映射为我们的 `SCHEMA_VIOLATION` / `OUT_OF_RANGE`。open-tabletop-gm 为 AGPL-3.0，禁止依赖或拷贝，仅借鉴「规则计算与叙事彻底分离」的原则；aequus 停更且模型过简，递归展开算法只有二十行，自行实现更省事。

拼接后边界：`calculate_craft_result` 是唯一数值权威，位于 `domain/crafting.py`，不依赖数据库；`CraftService` 负责校验、数值重算与草稿事件组装，不开启/提交事务、不调 `GameEngine`（提交只能由 GameEngine 在编排层调用链上完成）；生成路径的产物必须先过 Schema + 一致性检查才允许形成草稿事件（D-M4-3 仅约束草案不入队；工具执行仍走正常 Proposal 链，见 D-M4-13）。失败模式统一为 `Result.error_code`：`NOT_FOUND`（无配方）、`INVALID_INPUT`（数量/参数非法）、`OUT_OF_RANGE`（数值越界）、`NOT_ALLOWED`（工具/技能/越权）、`SCHEMA_VIOLATION`（自由草案未过 Schema）、`CONFLICT`（并发 CAS 失败，由 GameEngine 返回）。

### 本章结论
1. 制造双路径按 13.3 的表格硬编码判定，优先级固定为「确定性 > 生成 > 拒绝」，不得由 Agent 自行选择路径。
2. `calculate_craft_result` 是纯函数且为唯一数值权威，签名固定、种子由 `derive_seed(save_seed, turn_id, actor_id, "craft_item", next_seq)` 派生（§13.6），天然支持回放与回滚。
3. 生成路径只允许 LLM 产出「名称/描述/材料组合/效果 ID」，任何数值字段出现即判 `SCHEMA_VIOLATION`，统计量由框架重算。
4. 制造提交由 `GameEngine` 单事务完成（CAS + 幂等键），`CraftService` 只返回 `Result` 与草稿事件、绝不直接提交；失败零副作用，失败尝试由编排层写独立 `audit_events`（m2/m3/m4 同口径，含 m4 制造失败提案），保证审计与回放可查。
5. 配方数据模型从第一版就带 `version` 与质量分档，避免 M4 后期改结构导致旧事件无法回放。
6. 「近似配方」首版不做，作为 M4 后的待定项按三方案评估，不允许在没有验收标准前开放。
7. M4 按 §13.6 定案口径实现：模板/实例分离、技能后移、自由制造草案不入队（D-M4-3/D-M4-13）、种子由 `next_seq` 派生；本章与 §13.6 冲突的旧表述一律以 §13.6 为准。
