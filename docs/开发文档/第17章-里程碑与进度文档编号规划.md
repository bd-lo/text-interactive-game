### 17.3 vibe 会话 / 切片工作流
1. **任务描述模板**（直接复制到 AI 会话）：
```text
切片：<NNN>-<kebab-topic>
目标：<一句话，能演示>
最小上下文集：第 X 章 <小节> + 相关文件 <3–5 个> + 失败测试输出
约束：不得改红线（17.4）；不得新增依赖（除非先过第 19 章）；不得跨切片重构
验收命令：<lint/type + 相关单测 + demo 命令>
回滚点：<上一绿点 commit>
```
2. **最小上下文集**：对应章节段落 + 3–5 个相关文件 + 接口契约 + 失败输出；不投喂整仓、不投喂密钥/`.env`/生产数据。
3. **验收命令模板**：后端 `uv run ruff check . && uv run mypy src && uv run pytest -q -m "not slow"`；前端 `pnpm --dir web exec vue-tsc --noEmit && pnpm --dir web exec vitest run` + 本切片 e2e 子集。
4. **提交与回滚约定**：trunk-based，每切片 1–2 个 commit，前缀 `slice: NNN <topic>`；失败立即 `git revert` 或 reset 回上一绿点，**禁止在红树上继续堆改动**；连续 2 个切片失败 → 缩小切片并重写任务描述。
5. 每切片结束写 1 篇轻量进度文档（第 22 章 v0.3 模板，≤60 行）并同步 `docs/PROGRESS.md`；完成度按“已通过测试的任务数 / 总任务数”计算，不凭感觉填。

### 17.4 AI 生成代码的 review 清单
人工 review 每个切片的 diff，逐项勾选：
- [ ] **幻觉 API/依赖**：import 与调用真实存在，版本在锁定清单内（第 19 章）。
- [ ] **重复实现**：是否已有服务/工具/纯函数可复用（第 6、7 章）。
- [ ] **错误处理**：返回 `Result`/`ErrorCode`，不吞异常、不裸抛。
- [ ] **边界条件**：空值、超长输入、并发、幂等重复。
- [ ] **日志脱敏**：不打印密钥/令牌/Prompt 中的隐私字段。
- [ ] **许可证**：新拷贝代码的来源与许可合规（GPL/AGPL 只能参考设计）。
- [ ] **红线**：是否绕过唯一写入者/事件结构/actor_scope/LLM 校验链。
- [ ] **测试**：覆盖失败分支，而不是只有 happy path。

### 17.5 失败与回滚规则
**红线（AI 与人都不得绕过，改前必须人工发起）**：① 唯一写入者 `GameEngine`、事件溯源 `EventLog`、CAS 提交、`ProposalQueue/Resolver` 结构；② 确定性计算与智能体生成分离，LLM 输出必须过 JSON Schema；③ 权限/`actor_scope`/工具白名单不得放宽；④ 密钥、令牌、生产数据不进上下文与代码；⑤ 依赖/许可证（GPL/AGPL 只能参考设计）与第 5–7 章契约变更须人工确认。
- **切片失败即回滚**：停在上一绿点，不连续堆叠未验证改动；修复只有一个目标，修好再继续。
- **里程碑回滚**：001–028 编号不复用；revert 未合并 commit，进度文档记录原因、影响与回滚点；已合并的错误改动按事件/契约影响面评估是否发布 hotfix。
- **禁止 AI 自行“顺便重构”护栏模块**：唯一写入者、事件结构、Resolver、工具白名单的改动必须人类发起并 review。
- 依赖/许可证变更必须人工确认，`uv.lock`/`pnpm-lock.yaml` 变更单独提交。

#### 17.9.3 通用出口门禁（每批必须全绿）

1. **基线不回归**：全量 pytest（数字写进度文档）、replay 68（或迁移后新基线）、`demo --check` 7 屏与
   `console --check` 4 轮逐字不变（离线强制）；
2. **四门**：`ruff format --check`、`ruff check`、`mypy src`、`lint-imports`、`scripts/check_docs.py` PASS；
3. **web**：`pnpm test`、`typecheck`、`build`，tracked `web/dist` 与 fresh build 零漂移；
4. **e2e**：真实浏览器 25+ 步全绿；新增交互必须有步骤/断言（沿用 D-M6-11 的 CDP 口径，055 评估前不换工具）；
5. **文档同批**：ADR（含决策时）+ 进度文档 + `PROGRESS.md` §1/§3/§7 + 对应开发文档章节回写（`docs/开发文档.md` 重建）；
6. **契约同步**：`api/schemas.py` ↔ `web/src/api/types.ts` ↔ `web/src/api/client.ts` 运行时校验 ↔
   `tests/integration/test_frontend_contract.py` 四处同批更新；
7. **硬不变量**：唯一写入者/CAS/`Idempotency-Key`/用户 JSON 不执行/密钥不回显/旧 golden 逐字不变；
   新增 EventType 或 golden 重基线必须单独立 ADR（仅 033–034 与 054 两条路径）。

#### 17.9.4 启动顺序与偏离登记

- 建议顺序：**N4 049–053（发布就绪，可立即做）→ N1 029–032（内容）→ N2 037–040（流式）→ N3 → N4 054–056**；
- 用户指定优先级为「内容→体验→功能→技术→文档」，若用户要求「先发一个可下载版本」，允许 049–053 插队
  （本表不强制串行，只需在 `PROGRESS.md` §7 记录偏离原因）；
- 每次启动前：把切片对应行写进新进度文档（模板见第 22 章 §22.4），完成后回填 §3 索引与 §7 证据。

#### 17.9.5 明确不做（避免反复讨论）

- 账号体系 / 云存档 / 多用户 / 在线市场（分享只做文件交换，D-N5）；
- LLM 成本计费与 `llm_call_log`（D-M5-10 已定不做）；
- 世界书 `vectorized` 向量检索、`outlet` 宏插入、`characterFilter`（无宏/无 embedding 的设计决定，见兼容文档 §5）；
- 用户场景/世界书内执行脚本或表达式（安全红线，D-N5）；
- 默认引入 Playwright 长期 CI 矩阵（055 只评估）。
