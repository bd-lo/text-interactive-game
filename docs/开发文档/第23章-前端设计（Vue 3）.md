### 23.1 定位与边界：Web 客户端层

前端只占**Web 客户端层（Vue 3 SPA + TypeScript）**：负责展示与输入，不持有权威状态；所有写操作仍走 `接入层 API → 工具层 → Resolver → GameEngine（唯一写入者）→ EventLog`。前端拿到的 `TurnResult` 只是服务端一次提交的投影，页面状态可被服务端返回覆盖。

```text
浏览器（Vue 3 SPA；运行期零 Node 依赖）
  │ fetch /api/v1/*  JSON/FormData（写操作带 Idempotency-Key）
  ▼
FastAPI 接入层（/api/v1/*）＋ StaticFiles("/", directory="web/dist", html=True) ＋ SPA fallback
  ▼
TurnOrchestrator → ToolRegistry → RuleEngine/Resolver → GameEngine（唯一写入者）→ EventLog
```

| 前端负责 | 前端不负责 |
| --- | --- |
| 展示 80～150 字文本流、状态面板、回合历史、回放 | 判定、掷骰、数值计算、掉落（全部在后端 `RuleEngine`/`RandomSource`） |
| 收集指令与人物卡 brief、客户端预校验与错误提示 | 权威校验：服务端 JSON Schema + `GuardPipeline` 才是最终裁决 |
| 幂等键生命周期、错误码映射、断线重连、版本链维护 | 直接改 `GameState`、绕开 API 写库、持有写入权威 |
| 本地视图缓存与 UI 偏好（可丢弃、可恢复） | 长期保存游戏状态、事件日志、人物卡真身 |

构建期使用 Node（Vite/TypeScript/Vitest），**运行期不依赖 Node**：`pnpm --dir web build` 产出静态 `web/dist`，由 FastAPI 托管；部署机不需要安装 Node。

**SPA 深链（必需）**：`StaticFiles(html=True)` 只处理目录索引与已存在文件，**不做前端路由 fallback**；`/cards/:id`、`/games/:id/replay` 直接刷新会 404。FastAPI 必须注册 SPA fallback：非 `/api` 前缀且未命中静态文件的 GET 返回 `index.html`（第 16 章同步实现）；API 路由优先于 fallback。

**响应约定**：成功 → 200/201 直接返回业务 payload（`DELETE` 204 无 body），无 `{ok,data}` 信封；失败 → 4xx/5xx + `{ok:false, error_code, message, violations?}`。HTTP 映射：`INVALID_INPUT`→422（文件过大→413）、`SCHEMA_VIOLATION`→422（带 `violations`）、`NOT_FOUND`→404、`NOT_ALLOWED`→403、`CONFLICT`→409、`LLM_UNAVAILABLE`→503、`INTERNAL`→500；`OUT_OF_RANGE`：数值越界→422、限流→429（带 `Retry-After`）。

**类型契约**：`web/src/types/api.ts` 手写或由 `openapi-typescript` 从 FastAPI `/openapi.json` 生成；API client 不得裸 `body as T`，关键响应先做运行时校验/断言再返回。契约测试对比 OpenAPI 路径与前端类型（见 23.8）。

**幂等键生命周期**（`web/src/utils/idempotency.ts`）：每个“逻辑动作”（提交回合/导入/生成/保存/创建对局）在用户点击时生成一次 UUID，存 `sessionStorage`（键为动作标识，如 `turn:{gameId}:{turn}`），网络重试与页面恢复复用同一键；成功或最终失败后清除。`CONFLICT`（版本冲突）不是重试：应 `GET /games/{id}` 刷新 `version` 后由用户重新提交并生成**新键**。服务端语义：同键同参返回首次响应；同键异参 → `CONFLICT`。

```ts
// utils/idempotency.ts
export function getOrCreate(actionKey: string): string {
  const k = `idem:${actionKey}`
  const v = sessionStorage.getItem(k) ?? crypto.randomUUID()
  sessionStorage.setItem(k, v)
  return v
}
export function clear(actionKey: string) { sessionStorage.removeItem(`idem:${actionKey}`) }
```

```ts
// api/client.ts（要点：FormData 不手写 Content-Type；响应按类型契约校验后返回）
export async function request<T>(path: string, init: RequestInit & { idempotent?: boolean; actionKey?: string } = {}): Promise<T> {
  const headers = new Headers(init.headers)
  const isForm = init.body instanceof FormData
  if (!isForm && init.body !== undefined) headers.set('Content-Type', 'application/json')
  if (init.idempotent && init.actionKey) headers.set('Idempotency-Key', getOrCreate(init.actionKey))
  const resp = await fetch(`${API_BASE}${path}`, { ...init, headers })
  const body: unknown = resp.status === 204 ? null : await resp.json()
  if (!resp.ok) throw toApiError(body, resp.status)   // {ok:false, error_code, message, violations?}
  return parseResponse<T>(path, body)                 // 按 web/src/types/api.ts 校验后返回
}
```

横切能力：`app.config.errorHandler` + `ErrorBanner` 做错误边界；所有请求用 `AbortController`（路由离开/重复提交时取消）；`gameStore`/`uiStore` 持久化到 `sessionStorage`（恢复时先 `GET /games/{id}` 校验版本）；路由守卫在离开 `/games/:id` 且有未提交草稿时确认；离线时读缓存 + 只读重试队列（写请求不自动重放）；`/cards/:cardId` 的「开始游戏」调用 `createGame(card_id)`。

### 23.5 人物卡 JSON 上传

上传只接受单个 `.json` 文件且 **≤64KB**；客户端校验是体验优化，服务端 Pydantic 校验才是权威。

**后端已交付（M6B-3，2026-11-10）**：`GET /character-cards/schema`（draft 2020-12 Schema 对象本身）、`GET ""`（列表，默认 limit 20/上限 100）、`GET /{card_id}`、`POST /import`（multipart ≤64KB、source 强制 upload、`SOURCE_OVERRIDDEN` warning）、`POST /validate`（只读）、`POST ""`（保存，201）、`DELETE /{card_id}`（204 软删除）共 7 端点已入库；`POST /games` 支持 `card_id` 加法（D-M6-2）。**前端 026 已交付（2026-11-10，见上）**；本节的 UploadDropzone/Ajv 细化、`/cards/new`、详情删除/模板新建后移（D-M6-10）。`POST /character-cards/generate` 由 M6B-4 交付（§23.6）。

1. `UploadDropzone` 选择文件（支持拖放/粘贴）；检查扩展名、`size <= 64*1024`、UTF-8 可解码，超限按 `INVALID_INPUT` 提示（HTTP 413）。
2. 拉取或复用 `web/src/schemas/character-card.schema.json`（`GET /character-cards/schema` **直接返回 Schema 对象本身**；draft 2020-12，用 Ajv 的 `ajv/dist/2020` 构建加载）。
3. `JSON.parse` 失败 → 提示“JSON 语法错误（行列）”。
4. 用 Ajv2020（`strict: true, allErrors: true`）校验 CharacterCard 的 9 个字段（`schema_version`/`name`/`attributes`/`hp`/`starting_items`/`background`/`appearance`/`source`/`generated_by`）；客户端只报结构错误，跨字段约束（如 `hp <= max_hp`）与 trim/码点长度差异**只告警不阻断**，提交后由服务端裁决。
5. `CardPreview` 只读预览：`hp < max_hp` 是**合法受伤态**，不得标红；仅 `warnings` 与 Schema 错误展示为警告。
6. 确认后 `POST /character-cards/import`（multipart，带 `Idempotency-Key`，`FormData` 由浏览器自动加 boundary）；服务端解析 + Schema 校验 + 内容安全 + 规范化，成功 201 `{card_id, card, warnings}`。
7. 成功后跳 `/cards/:cardId`；失败停留预览态，按错误码提示。

| 失败分支 | 触发点 | 处理 |
| --- | --- | --- |
| 文件过大 | 步骤 1 | `INVALID_INPUT`（HTTP 413），提示 64KB 限制，不发请求 |
| 文件类型错 | 步骤 1 | `INVALID_INPUT`（HTTP 422），仅接受 `.json` |
| JSON 语法错/非 UTF-8 | 步骤 3 | `INVALID_INPUT`，展示解析位置 |
| Schema 不符/字段越界 | 步骤 4/6 | `SCHEMA_VIOLATION`（带 `violations`） |
| 内容安全拒绝 | 步骤 6 | `NOT_ALLOWED`，提示修改 `background`/`appearance` |
| 资源不存在（模板/文件） | 步骤 6 | `NOT_FOUND`，提示刷新后重试 |
| 同键异参/重复提交 | 步骤 6 | `CONFLICT`（同键同参则返回首次响应） |
| 限流/网络/5xx | 步骤 6 | 429 按 `Retry-After` 等待；网络错误保留键可安全重试；5xx 提示稍后重试 |

`warnings` 形状统一为 `[{code, message, field?}]`（第 6/21 章一致），如 `{"code":"DUPLICATE_ITEM_MERGED","message":"duplicate starting item merged","field":"starting_items"}`。

```json
{
  "schema_version": "1.0",
  "name": "灰烬旅人",
  "attributes": {"str": 12, "dex": 14, "con": 11, "int": 15, "wis": 10, "cha": 8, "max_hp": 30},
  "hp": 30,
  "starting_items": ["item_torch", "item_rusty_knife"],
  "background": "在旧矿镇长大的拾荒者，靠辨认废矿里的风声过活。",
  "appearance": "煤灰斗篷，左眉有一道旧疤。",
  "source": "upload",
  "generated_by": null
}
```

成功响应（HTTP 201，直返 payload）：

```json
{
  "card_id": "card_01J9Z3K4Q7...",
  "card": {
    "schema_version": "1.0",
    "name": "灰烬旅人",
    "attributes": {"str": 12, "dex": 14, "con": 11, "int": 15, "wis": 10, "cha": 8, "max_hp": 30},
    "hp": 30,
```

失败响应（4xx/5xx）：`{"ok": false, "error_code": "SCHEMA_VIOLATION", "message": "character card schema violation", "violations": [{"loc": ["hp"], "type": "value_error", "msg": "hp must be <= attributes.max_hp"}]}`。

**校验等价性规则**：`attributes` 正负值域写进共享 Schema；`max_hp` 必须 ≥1（否则 `hp>=0` 与 `hp<=max_hp` 无解），该规则需第 5 章 §5.7 同步；服务端 trim 后再计长度，客户端按 `[...str].length`（码点）预估，禁止用 UTF-16 `length` 直接等价。

### 23.6 LLM 生成 JSON 人物卡

1. `GenerateCardForm` 收集 `brief`（≤1000 字符）与 `schema_version`/`options`；提交前校验长度与空值。
2. `POST /character-cards/generate`：客户端在点击时生成 UUID 幂等键（**不是 `sha256(brief)`**），网络重试复用同一键；服务端按键去重，`brief`/`schema_version`/`options` 参与请求哈希，**同键异参 → `CONFLICT`**；限流按 **IP+session** 计（本地单机无账号，部署多用户再加鉴权），5 次/分钟。
3. 服务端 `LLMRequest(task="character_card_generate", model_tier=STRONG, max_repair=1, timeout_s=20)` 经 `LLMClient.complete_json` 生成（第 12 章），先过 JSON Schema 再走内容安全（第 15 章 `GuardPipeline`）。
4. 成功 200 `{draft, validation, generated_by}`；`draft.source="llm"`、`generated_by` 为模型/供应商标识（仅审计）。**未保存、未开局。**
5. `CardPreview` 以“草稿”标识展示，可编辑但仅作再次校验；不提供“保存即开局”。
6. 确认保存调用 `POST /character-cards`（body 为已校验 CharacterCard，服务端重校验 + 强制 `card_id`/`source`，带幂等键），201 `{card_id, card}`；保存前禁止自动创建游戏/跳转对局。
7. 失败不写状态：`SCHEMA_VIOLATION` 提示修改 brief；`LLM_UNAVAILABLE` 提示稍后重试或选模板草稿；`NOT_ALLOWED` 为内容安全拒绝；429 按 `Retry-After` 等待（`error_code=OUT_OF_RANGE`）。

### 23.7 安全

- **XSS**：禁 `v-html`/`innerHTML`/`eval`；文本走 `{{ }}`；JSON 预览 `<pre>{{ JSON.stringify(card, null, 2) }}</pre>`；CI grep 级检查阻止 `v-html` 进入 `web/src`。
- **CSP**：同源默认 `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'self'; frame-ancestors 'none'`。**API 地址可配置与 `connect-src 'self'` 冲突**：同源部署按默认；分离部署时由后端按配置把 API 域名加入 `connect-src`；开发期用 Vite proxy 保持同源。
- **CORS/CSRF**：同源部署（FastAPI 托管 `web/dist` + `/api/v1`）无 Cookie 鉴权时 CSRF 不适用；分离部署需显式 allowlist（禁通配符）+ CSRF token。
- **上传/生成**：大小/类型/解析/字段白名单/禁止可执行内容均在服务端再做；brief 只作为消息数据；限流 + 成本归集；错误日志脱敏（只记 `request_id` 与错误码，不落完整卡面/brief/API Key）。
- **供应链**：`pnpm-lock.yaml` 锁版本、`--frozen-lockfile`、`pnpm audit` + 许可证扫描（第 19 章）；禁止 CDN 脚本。

### 本章结论

1. 前端定位固定为 **Web 客户端层**：只展示/输入，权威状态与判定在后端；唯一写入者仍是 `GameEngine`，Node 只在构建期参与，`web/dist` 由 FastAPI 托管并需 SPA fallback。
2. 技术栈定稿：Vue 3.5.45 + Vue Router 5.4.0 + Pinia 4.1.0 + Ajv 8.20.0 + Vite 8.3.6 + Vitest 5.1.0 + `@playwright/test` 1.65.0，构建期 Node 24.x LTS；TypeScript 5.9.x 为 M6 基线，版本统一以第 19 章 §19.7 为准。
3. 对局一致性靠**版本链 + 幂等键**：`version` 只由服务端返回（创建/回合/刷新），`expected_version` 永远取当前 `version`；逻辑动作一个 UUID 键贯穿重试，`CONFLICT` 后刷新再让用户重新提交。
4. 人物卡两条路径共用 9 字段 CharacterCard Schema：客户端 Ajv 仅体验校验、服务端 Pydantic 权威；上传失败覆盖 413/422/404/409/429/5xx，生成统一 `LLMRequest(task="character_card_generate", STRONG, max_repair=1)`，模板兜底 `source=manual`、`generated_by=null` 且带 `TEMPLATE_FALLBACK` 警告。
5. 执行建议：F1（025）先落地骨架 + 类型契约 + API client + 深链 fallback + 错误边界；F2/F3（026/027）并行；F4（028）待 M5 就绪接入；安全项（禁 `v-html`、CSP、限流、日志脱敏、存储型注入定界）列入 F1 验收。
